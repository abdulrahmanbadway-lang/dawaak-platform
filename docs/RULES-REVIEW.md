# مراجعة قواعد الأمان (firestore.rules)

> **مهم:** القواعد دي **ما اتشغّلتش على Firestore Emulator** (مفيش Emulator في بيئة التطوير). المراجعة دي قراءة يدوية للملف مقابل الكود اللي بيكتب في Firestore. اختبر الطلبات فعليًا بعد كل نشر (docs/MANUAL-TESTS.md).

## اللي بتفرضه القواعد فعلًا (Enforced)
| المجال | اللي بيتفرض |
|---|---|
| الأدوار | `role` مينفعش المستخدم يغيّره بنفسه، ولا يسجّل نفسه أدمن. الأدمن بس يرقّي مريض لأدمن (ومش نفسه) |
| الحظر | `blocked` يتغيّر من الأدمن بس، والمحظور بيفقد الكتابة وقراءة الطلبات والروشتات |
| توثيق الصيدلية | الصيدلية متقدرش تغيّر `verified` ولا `status` ولا الترخيص ولا اسم المسؤول |
| طلب السلة | السعر والاسم والجرعة والمخزون (≥ الكمية) والصيدلية بتتراجع من مستند المنتج نفسه، المنتج مش روشتة، الكمية 1-20، حد أقصى 8 أصناف، الإجمالي = مجموع الأسطر، اسم المريض = اسم حسابه |
| شكل الطلب | `phone` 8-20 حرف، `address` 5-300، `note` ≤ 500، `createdAt/updatedAt` = وقت السيرفر، الحالة الأولى `new` |
| طلب الروشتة | الأصناف والإجمالي والصيدلية مطابقة لعرض الصيدلي بالظبط، والروشتة لسه `quoted`، والطلب والروشتة في batch واحد |
| انتقالات الطلب | الصيدلية: new→preparing/cancelled، preparing→out (مع مندوب مربوط بيها)، out→done. المندوب المعيّن: out→done. المريض: new→cancelled |
| تتبع المندوب | بيكتبه المندوب المعيّن والطلب `out` بس، وإحداثيات صالحة |
| المنتجات | صاحب الصيدلية بس يكتب/يحذف منتجاته. السعر رقم موجب والكمية ≥ 0 والصورة JPEG مضغوطة أو https. الأدمن يغيّر الصورة بس |
| الروشتات | صاحبها وصيدليتها والأدمن بس يقروها. انتقالات الحالة محددة، ومفيش حذف |
| المستندات الرسمية | صاحب الصيدلية والأدمن بس، وتتبدّل لحد التوثيق |
| الآراء | رأي واحد لكل مريض والاسم من حسابه |

## اللي **مش** مفروض بالقواعد (قيود معروفة)
1. **خصم المخزون عند القبول** بيتم من المتصفح (transaction في لوحة الصيدلية). القواعد بتتأكد إن المخزون كفاية وقت إنشاء الطلب بس. صيدلية متلاعبة تقدر تقبل من غير خصم (ضرر على نفسها بس). الحل الكامل يحتاج Cloud Functions (مدفوع، خارج الخطة).
2. **حد 10 قراءات مستند في الطلب الواحد**: عشان كده السلة بحد أقصى 8 أصناف لكل طلب.
3. **تواجد الزوار (`presence`) والاحتياج (`demand`)** بيقبلوا كتابة من أي زائر بشكل محدد الحجم والأنواع. ممكن حد يزوّر IP أو يعمل ضغط كتابة. تأثيرهم عرض في لوحة الأدمن بس. (App Check هو الحل ولو متاح مجانًا فعّله لاحقًا).
4. **الأدمن يقدر يقرا مستند الروشتة كامل بالصور.** لوحة الأدمن مابتعرضش الصور، لكن الصلاحية موجودة في القواعد. اعتبر حساب الأدمن حساس جدًا وما تديهوش لأي حد.
5. **الحظر** بيمنع الكتابة وقراءة الطلبات والروشتات، لكن المحظور لسه بيقدر يسجّل دخول ويقرا المنتجات والصيدليات (عامة)، ويقدر يفتح حساب جديد بإيميل تاني.
6. **الصيدلية بعد التوثيق** تقدر تغيّر اسمها وعنوانها وموقعها (القواعد بتمنع الترخيص واسم المسؤول والتوثيق بس).
7. **مناديب الصيدلية**: أي حساب يقدر يسجّل نفسه `courier`، لكن من غير مستند `couriers/{uid}` تربطه صيدلية مابيشوفش ولا يوصّل أي طلب. أول صيدلية تنشئ مستند المندوب هي اللي بتربطه.
8. **التسجيل الذاتي كصيدلية** مسموح، لكن الصيدلية متظهرش للمرضى إلا بعد توثيق الأدمن.
9. **الدخول برقم الموبايل (`loginIds/{الرقم}`)**: أي حد يعرف الرقم يقدر يقرا وثيقته (`get` بس، مفيش `list`) فيعرف إيميل صاحب الحساب. ده تنازل مقصود علشان الدخول بالرقم يشتغل قبل تسجيل الدخول. القواعد بتمنع حجز رقم محجوز، ورقم واحد لكل حساب، وإيميل الفهرس لازم يطابق إيميل الحساب الفعلي. **الرقم نفسه مش متأكد منه بـ SMS** (الخطة المجانية مفيهاش Phone Auth)، فهو اسم دخول مش إثبات هوية.

## تعديلات المراجعة دي
- `shapeOk()` للطلبات: أنواع وأحجام الحقول وتوقيت السيرفر (قبلها `createdAt` و`phone` و`address` ماكانتش متحقّق منها).
- `patientName` في طلب السلة لازم يطابق اسم الحساب (منع تزوير الاسم).
- `pharmacyName` في طلب الروشتة لازم يطابق اسم الصيدلية في الروشتة.
- `valOk()` للمنتجات: سعر موجب ≤ 1,000,000، كمية ≥ 0، اسم 2-150 حرف.

## قبل النشر
```bash
firebase deploy --only firestore:rules
```
ولو أي حاجة اتكسرت (مثلًا "Missing or insufficient permissions" عند إرسال طلب عادي)، ارجع للنسخة السابقة من `firestore.rules` (`apply-<الباتش>.sh --rollback`) وابعتلي رسالة الخطأ بالظبط.
